# 02 · 架构设计

## 分层架构总览

本项目采用**三层分层 + 横切关注点**的架构组织方式。从下到上依次为：纯逻辑层（modules/utils）→ 行为复用层（hooks）→ 视图组件层（components）。

```
┌─────────────────────────────────────────────────────────────┐
│                     components（视图层）                       │
│   Masonry · Menu3D · Shimmer · BorderEffect · PartitionLayout · Cube   │
│        依赖 hooks + modules，对外暴露声明式 props / ref API         │
└──────────────────────────┬──────────────────────────────────┘
                           │ 组合 / 复用
┌──────────────────────────┴──────────────────────────────────┐
│                       hooks（行为复用层）                      │
│  useEvent(基石) · useMounted · useWindowSize · useBoxSizeObserver     │
│  useMouseDragOffset · useScrollPercent · useMockProgress · useAutoLoadMore │
│        封装 React 状态与副作用，对下消费 modules/utils              │
└──────────────────────────┬──────────────────────────────────┘
                           │ 可选依赖
┌──────────────────────────┴──────────────────────────────────┐
│              modules / utils（纯逻辑层，框架无关）              │
│  SyncTaskQueue · UniqueRequest · VerticalViewportMonitor · AsyncUtil    │
│        不依赖 React，可独立测试与跨框架复用                       │
└─────────────────────────────────────────────────────────────┘
```

### 分层原则

1. **依赖方向单向向下**：components 可依赖 hooks/modules，hooks 可依赖 modules/utils，但 modules/utils **绝不向上依赖** React。例如 [SyncTaskQueue](../packages/ui-components/src/modules/SyncTaskQueue.ts)、[UniqueRequest](../packages/ui-components/src/modules/UniqueRequest.ts) 全部是纯 class，无任何 React import。
2. **同层解耦**：同层模块之间尽量避免横向依赖。hooks 之间仅存在少量「基石复用」——例如 `useMouseDragOffset`、`useAutoLoadMore`、`useScrollPercent` 都复用 [useEvent](../packages/ui-components/src/hooks/useEvent.ts)。

## 入口聚合策略

所有能力通过 [src/index.ts](../packages/ui-components/src/index.ts) 的 `export *` 聚合，每个子目录都有自己的 barrel 文件（`index.ts`）：

```
src/index.ts
├── components/index.ts  → 各组件 index.tsx（再 export models / types）
├── hooks/index.ts       → 各 hook 文件
├── modules/index.ts     → 各 module 文件
└── utils/index.ts       → export * as AsyncUtil
```

> ⚠️ 这种「层层 `export *`」会带来命名冲突风险，因此库内约定：**类型与类名全局唯一，hook 必以 `use` 开头**。

## 组件内部架构模式

### 模式 A：props → CSS 变量 → 样式（运行时样式驱动）

`Shimmer`、`BorderEffect`、`Cube` 三个组件采用统一模式：不把数值 props 写进内联 style，而是通过 `useEffect` 写入 CSS 自定义属性，再由 Less 动画消费。

以 [Shimmer](../packages/ui-components/src/components/Shimmer/index.tsx) 为例：

```tsx
useEffect(() => {
    containerRef.current?.style.setProperty("--shimmer-width", `${width}px`);
}, [width]);
```

对应 [style.module.less](../packages/ui-components/src/components/Shimmer/style.module.less) 中由 `var(--shimmer-width)` 驱动动画。

**好处**：动画由 CSS 负责（GPU 友好、不触发 React 重渲染），props 只负责「刷一次变量」。

### 模式 B：逻辑外置 class + hook 消费（Masonry 模式）

复杂组件 [Masonry](../packages/ui-components/src/components/Masonry/index.tsx) 把核心算法下沉为纯 class [MasonryLayout](../packages/ui-components/src/components/Masonry/models/MasonryLayout.ts)，再用一组 hooks 桥接 React：

```
Masonry (index.tsx, 视图 + forwardRef)
 ├── useColumnCount        ← 列数计算（断点 / maxColumnCount）
 ├── useScrollViewArea     ← 可见区域 + 触底加载更多
 ├── useMasonryLayout      ← 持有 MasonryLayout 实例，驱动 reLayout
 └── useResizeObserver     ← 容器尺寸变化
         ↑
   MasonryLayout (class)   ← 纯算法：找最短列、计算高度、可视区裁剪
```

`useMasonryLayout` 通过 `useRef` 持有 `MasonryLayout` 实例，把 React 状态（`viewableItemsLayout`）作为 class 计算结果的「投影」。这是「**命令式实例 + 声明式投影**」的典型写法。

### 模式 C：ref + useImperativeHandle（命令式逃生舱）

当外部需要主动控制组件（滚动、定位），组件用 `forwardRef` 包裹并通过 `useImperativeHandle` 暴露受控方法。Masonry 暴露的 [MasonryRef](../packages/ui-components/src/components/Masonry/types.ts)：

```ts
export type MasonryRef = {
    getScrollElement: () => HTMLElement | null
    scrollToTop: (behavior?: ScrollBehavior) => void
    scrollIntoView: (id: string | number) => void
}
```

## 容器引用统一约定

全库对「DOM 容器」参数统一采用 **`HTMLElement | (() => HTMLElement)`** 联合类型，并在内部用相同的 resolve 模式：

```ts
const resolveContainer = (c: HTMLElement | (() => HTMLElement)) =>
    typeof c === 'function' ? c() : c
```

见 [useScrollPercent](../packages/ui-components/src/hooks/useScrollPercent.ts)、[useAutoLoadMore](../packages/ui-components/src/hooks/useAutoLoadMore.ts)、[useColumnCount](../packages/ui-components/src/components/Masonry/hooks/useColumnCount.ts) 等。

**原因**：ref.current 在 hook 调用时可能尚为 null，传入函数可延迟求值，避免拿不到元素。

## 回调稳定化：useEvent 模式

库内几乎所有事件回调都经过 [useEvent](../packages/ui-components/src/hooks/useEvent.ts) 包裹：

```ts
export function useEvent<T extends (...args: any[]) => any>(callback: T) {
    const callbackRef = useRef(callback);
    callbackRef.current = callback;            // 每次渲染更新最新引用
    return useCallback((...args) => callbackRef.current(...args), []);
}
```

它返回一个**引用永远稳定**的函数，但调用时执行的是最新的 callback。借此：
- 给 `addEventListener` / `ResizeObserver` 的回调不会因闭包陈旧而读到旧 state；
- 也不必把 callback 放进 effect 依赖数组导致频繁重订阅。

> 这是本库的「基石 hook」，详见 [useEvent 稳定回调模式](./guides/useEvent-稳定回调模式.md)。

## 数据流：以 Masonry 为例

```
items(props) ──► useMasonryLayout ──► MasonryLayout.reLayout()
                                          │ 计算 columnWidth / 高度 / 分列
                                          ▼
                  viewableItemsLayout ◄── getViewableItemsLayout()
                          │
scroll ──► useScrollViewArea ──► viewRange ──► setOptions({viewRange})
                                          │ 触发 reCalcViewArea() 裁剪
                                          ▼
                  viewableItemsLayout ◄── getViewableItemsLayout()  → 重渲染
resize ──► useResizeObserver ──► onResize(debounce) ──► reLayout + reCalc
```

关键点：滚动只更新 `viewRange`（轻量），列数/数据变化才触发 `reLayout`（全量），resize 用 `debounce(10ms)` 合并。详见 [Masonry](./components/Masonry.md)。

## 文档与库的协同

文档站点 [site/](../site/) 在开发期通过别名直接引用库源码（非 dist）：

```ts
// rspress.config.ts → builderConfig.resolve.alias
'@mmjg/ui-components': '../packages/ui-components/src/index.ts'
```

而库 [package.json](../packages/ui-components/package.json) 的 `exports` 字段对 `development` 条件也指向 `./src/index.ts`，`production` 才指向 `./dist/index.js`。这保证文档站永远调试最新源码，发布产物走打包后的 `dist`。

## 架构决策记录（ADR 摘要）

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 打包工具 | Rolldown | Rust 实现，ESM 产物 + dts 一体化 |
| 样式方案 | Less + CSS Modules | 隔离样式 + 自定义哈希 `[name]__[local]___[hash:base64:5]` |
| 运行时主题 | CSS 自定义属性 | 避免 JS 重渲染，动画交给 CSS |
| 状态桥接 | class 实例 + useRef + useState 投影 | 复杂算法脱离 React 调度，按需触发渲染 |
| 版本管理 | Changesets | monorepo 友好的版本与 changelog 自动化 |
| 文档框架 | Rspress | 内置 preview 插件，支持 mdx 实时预览 |
