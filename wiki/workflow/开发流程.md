# 开发流程

## 简介

本页描述参与 `@mmjg/ui-components` 开发的标准流程：从环境准备、依赖安装、文档站调试，到库构建与提交规范。所有命令均定义在仓库根 [package.json](file:///Users/linjianguang/code/repo/ui-components/package.json) 的 `scripts` 字段中，通过 pnpm monorepo 的 `--filter` 机制分发给各工作区执行。

## 环境准备

项目对工具链版本有明确约束，开发前需确保本机环境匹配：

| 依赖 | 要求版本 | 来源 |
| --- | --- | --- |
| Node.js | `^20.19.0 \|\| >=22.12.0` | [packages/ui-components/package.json](file:///Users/linjianguang/code/repo/ui-components/packages/ui-components/package.json) 的 `engines.node` |
| pnpm | `10.12.1` | 根 [package.json](file:///Users/linjianguang/code/repo/ui-components/package.json) 的 `packageManager` 字段 |

准备步骤：

```bash
# 1. 克隆仓库
git clone https://github.com/MMJG-Team/ui-components.git
cd ui-components

# 2. 确认 Node 版本满足要求
node -v

# 3. 启用正确的 pnpm 版本（corepack 会读取 packageManager 字段）
corepack enable
corepack prepare pnpm@10.12.1 --activate
```

> 仓库采用 pnpm workspace（见 [pnpm-workspace.yaml](file:///Users/linjianguang/code/repo/ui-components/pnpm-workspace.yaml)），包含两个工作区：`packages/ui-components`（库本体）与 `site`（文档站）。

## 安装依赖

使用冻结的 lockfile 安装，保证依赖版本与 CI 环境一致：

```bash
pnpm install --frozen-lockfile
```

`--frozen-lockfile` 会拒绝在 lockfile 与 `package.json` 不一致时进行变更，从而避免本地引入未提交的依赖漂移。CI 流水线同样使用该命令（见 [CI/CD 自动化](./CI-CD-自动化.md)）。

## 启动文档站

```bash
pnpm run dev
```

该命令等价于 `pnpm --filter ./site run dev`，进入 `site` 工作区执行其 `dev` 脚本 `rspress dev --port 9010`。文档站基于 [Rspress](https://rspress.dev/) 搭建，启动后访问：

```
http://localhost:9010
```

文档站的配置见 [site/rspress.config.ts](file:///Users/linjianguang/code/repo/ui-components/site/rspress.config.ts)。

## 调试说明

文档站并非依赖已发布的 npm 产物，而是通过别名直接指向库的源码。在 [rspress.config.ts](file:///Users/linjianguang/code/repo/ui-components/site/rspress.config.ts) 的 `builderConfig.resolve.alias` 中：

```ts
alias: {
    '@assets': './docs/assets',
    "@demo": './docs/_demo',
    '@mmjg/ui-components': '../packages/ui-components/src/index.ts'
}
```

这意味着：

- 文档站中 `import { Masonry } from "@mmjg/ui-components"` 实际解析到 [packages/ui-components/src/index.ts](file:///Users/linjianguang/code/repo/ui-components/packages/ui-components/src/index.ts)。
- 直接编辑 `packages/ui-components/src` 下的源码，文档站会热更新（hot-reload），所见即所得。
- 无需在调试期间反复执行 `build:ui-components`，调试效率更高。

此外，`site` 的 [package.json](file:///Users/linjianguang/code/repo/ui-components/site/package.json) 通过 `"@mmjg/ui-components": "workspace:*"` 以 workspace 协议引用库，类型解析在开发期走 `exports` 的 `development` 条件（指向 `./src/index.ts`），生产期走 `production` 条件（指向 `./dist`）。

## 构建库

```bash
pnpm run build:ui-components
```

该命令等价于 `pnpm --filter ./packages/ui-components run build`，进入库工作区执行 `rolldown -c ./rolldown.config.ts`，由 Rolldown 将 TypeScript + Less 源码打包为 ESM 产物，输出到 [packages/ui-components/dist/](file:///Users/linjianguang/code/repo/ui-components/packages/ui-components) 目录。构建细节见 [构建与发布](./构建与发布.md)。

构建文档站则使用：

```bash
pnpm run build:docs
```

等价于 `pnpm --filter ./site run build`，执行 `rspress build`，产物输出到 `site/doc_build`（由 CI 上传并部署到 GitHub Pages）。

## 提交规范

本项目使用 [Changesets](https://github.com/changesets/changesets) 管理版本与变更日志，而非手动维护 `CHANGELOG`。每次提交有意义的变更后，应新增一个变更集（changeset）：

```bash
pnpm exec changeset
```

交互式选择受影响的包（`@mmjg/ui-components`）、版本提升类型（`patch` / `minor` / `major`）并填写变更说明，会在 [.changeset/](file:///Users/linjianguang/code/repo/ui-components/.changeset) 目录下生成一个带随机 slug 的 Markdown 文件。详细的版本提升流程与示例见 [Changesets 版本管理](./Changesets-版本管理.md)。

> 根 [package.json](file:///Users/linjianguang/code/repo/ui-components/package.json) 的 `devDependencies` 包含 `@changesets/cli`，提供 `changeset` 命令行工具。

## 相关脚本一览

下表汇总根 [package.json](file:///Users/linjianguang/code/repo/ui-components/package.json) 中与开发流程相关的脚本：

| 脚本 | 实际执行 | 用途 |
| --- | --- | --- |
| `dev` | `pnpm --filter ./site run dev` | 启动文档站（端口 9010） |
| `build:docs` | `pnpm --filter ./site run build` | 构建文档站到 `site/doc_build` |
| `build:ui-components` | `pnpm --filter ./packages/ui-components run build` | Rolldown 打包库到 `dist/` |
| `publish:ui-components` | `pnpm --filter ./packages/ui-components run publish` | 发布库到 npm（CI 中调用） |
| `prepublishOnly` | `pnpm run build:ui-components` | 发布前生命周期钩子，先构建 |
